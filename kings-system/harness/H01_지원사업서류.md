# H01 · 지원사업 서류 하네스

## 1. 목적과 위임 단계
- 목적: 공고 1건에 맞춘 사업계획서 초안을 **평가 항목 기준으로** 작성하고, 숫자와 사실을 검증한다
- 위임 단계: **2** (대표가 방향·핵심 내용을 정하고, AI가 작성·검토를 지원)
- 대표만 하는 일: 신청 여부 결정, 사업 목표·예산 확정, 최종 문장 승인, 발표

## 2. 역할

| 역할 | 맡은 일 | 명세 6칸 요약 |
|---|---|---|
| **A1 공고 분석가** | 공고문·평가 기준표를 읽고 요구 사항을 표로 정리 | 목표: 평가 항목별 배점·요구 증빙 표 / 자료: 공고문 원문만 / 조건: 해석 대신 원문 인용 / 형식: 항목-배점-요구-증빙 표 / 기준: 공고에 없는 내용 금지 |
| **A2 자료 수집가** | 킹스 데이터에서 근거 자료를 모은다 | 자료: 문장 은행, 마스터 사업계획서, 실적 집계(매출·생산·고용), 인증·수상 / 조건: 기밀(레시피·원가 상세) 제외 / 형식: 평가 항목별 근거 목록 |
| **A3 작성자** | 평가 항목 순서대로 초안을 쓴다 | 맥락: 읽는 사람은 평가위원, 짧은 시간에 여러 서류를 본다 / 조건: 개조식, 과장 금지, 숫자는 A2 자료만 / 형식: 공고 양식 목차 그대로 |
| **A4 평가위원 검토자** | 평가위원 입장에서 점수를 매기고 약점을 지적 | 기준: 항목별 예상 점수, 근거 부족 문장, 모호한 표현, 빠진 증빙 / **A3과 다른 AI 또는 다른 세션** |
| **A5 숫자·사실 검증자** | 모든 숫자·날짜·고유명사를 원자료와 대조 | 기준: 불일치=치명, 출처 없음=치명, 단위 오류=주의 |

## 3. 순서
```
A1 공고 분석 ─┐
              ├─▶ A3 작성 ─▶ A4 평가 검토 ─▶ A5 숫자 검증 ─▶ 대표 확인
A2 자료 수집 ─┘        ▲                          │
                       └──── 치명 오류 시 되돌림 ──┘
```
A1과 A2는 동시에 진행한다.

## 4. 넘김 (파일)
| 단계 | 파일 |
|---|---|
| A1 | `01_공고분석표.md` |
| A2 | `02_근거자료.md` |
| A3 | `03_초안.md` |
| A4 | `04_평가검토.md` (항목별 예상 점수, 약점 목록) |
| A5 | `05_검증보고서.md` (치명·주의·참고) |
| 최종 | `06_최종본_대표승인.hwpx` (대표가 양식에 옮김) |

## 5. 검수
| 기준 | 판정 |
|---|---|
| 평가 항목 중 빠진 항목이 있다 | 치명 |
| 숫자가 원자료와 다르다 / 출처가 없다 | 치명 |
| 사실이 아닌 실적·계획을 실적처럼 썼다 | 치명 |
| 지원사업 AI 사용 공개 규정 위반 (공고 확인) | 치명 |
| 분량 초과, 문장이 길다, 상투어("혁신적인", "차별화된") | 주의 |
| 더 강한 표현 제안 | 참고 |

되돌림: 치명 1건 이상 → A3로 되돌리고 대표에게 알림. 2회 연속 되돌림 → 대표가 직접 해당 항목을 쓴다.

## 6. 실행
- 명령: `kings run H01 G-27-03` (지원사업 코드)
- 입력: 공고문 파일, 평가 기준표, 사업 목표 메모(대표 작성 5줄)
- 데이터 등급: 공개·내부 / 기밀 제외
- provider: cloud 기본, 기밀 포함 시 local

## 7. AI off 대안
마스터 사업계획서 + 문장 은행에서 평가 항목별 문단을 골라 붙인다. 숫자는 월 결산 보고서에서 옮긴다. A4·A5는 대표가 체크리스트로 직접 한다.
