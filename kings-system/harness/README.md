# 킹스 하네스 — AI용 업무 매뉴얼

> 하네스는 코드가 아니라 **말로 쓴 문서**다. AI 모델이 바뀌어도 이 문서는 그대로 쓴다.
> 이 폴더가 킹스양조장 AI 경쟁력의 본체다. (모델은 빌려 쓰고, 하네스는 내가 가진다.)

---

## 1. 대표가 알아야 할 AI 지식 12가지

| # | 용어 | 뜻 | 킹스양조장에서의 의미 |
|---|---|---|---|
| 1 | 모델 | AI의 두뇌 (클라우드 AI, 로컬 AI) | 몇 달마다 바뀐다. **갈아 끼우는 부품**으로 본다 |
| 2 | 프롬프트 / 명세 | AI에게 주는 지시 | 명세 6칸으로 쓴다 (목표·맥락·자료·조건·형식·기준) |
| 3 | 컨텍스트 | AI가 한 번에 보고 기억하는 자료의 범위 | 자료를 너무 많이 주면 흐려진다 → **필요한 자료만** 골라 준다 |
| 4 | 환각 | AI가 근거 없이 그럴듯하게 지어내는 것 | 숫자는 반드시 DB에서, 모르면 "확인 필요" |
| 5 | 토큰 | AI가 읽고 쓰는 글자 단위, **요금의 기준** | 하네스마다 실행 비용을 기록한다 |
| 6 | 에이전트 | 스스로 여러 단계를 실행하는 AI | 협업 3·4단계 업무를 맡는다 |
| 7 | 하네스 | 여러 에이전트를 팀처럼 움직이는 업무 매뉴얼 | 역할·순서·넘김·검수·실행 5부품 |
| 8 | MCP | AI를 도구·데이터에 연결하는 표준 배관 | kings.db·폴더·캘린더를 AI에 연결하는 방식. **배관은 내 데이터 쪽에** |
| 9 | 지식 검색 (RAG) | AI가 내 문서를 찾아 읽고 답하는 방식 | 지식 창고: SOP·서류·문장 은행 검색 |
| 10 | 로컬 AI | 내 PC에서 인터넷 없이 도는 AI | 비상 동력. 기밀 데이터는 로컬로만 |
| 11 | AEO | AI 답변 엔진에 선택되도록 정보를 만드는 것 | 스펙·수치, 표·FAQ, 공식 출처 |
| 12 | 검증 | AI 결과를 다른 AI·규칙·사람이 확인하는 것 | **만드는 AI와 검사하는 AI를 가른다** |

## 2. 명세 6칸과 하네스의 관계

| 구분 | 명세 6칸 | 하네스 |
|---|---|---|
| 대상 | AI 한 명에게 일 하나 | AI 여러 명이 팀으로 일 한 묶음 |
| 비유 | 업무 지시서 한 장 | 부서 업무 매뉴얼 |
| 구성 | 목표·맥락·자료·조건·형식·기준 | 역할·순서·넘김·검수·실행 (각 역할 안에 명세 6칸) |

## 3. 모든 하네스의 공통 규칙

1. **만드는 AI와 검사하는 AI를 가른다.** 같은 AI가 쓰고 검사하지 않는다.
2. **숫자는 데이터베이스에서만.** AI가 숫자를 만들지 않는다. 자료에 없으면 "확인 필요".
3. **단계마다 파일로 넘긴다.** `실행ID/01_…md`, `02_…md` 순서로 남긴다.
4. **치명 오류면 되돌린다.** 검수에서 치명 판정이 나오면 작성 단계로 돌리고 대표에게 알린다.
5. **대표가 최종 승인한다.** 외부로 나가는 모든 결과물은 대표 확인 뒤 사용한다.
6. **데이터 등급을 지킨다.** 기밀·개인정보는 클라우드 AI로 보내지 않는다 (docs/08 5장).
7. **실행을 기록한다.** 하네스 코드·버전·provider·통과 여부·비용을 `harness_runs`에 남긴다.
8. **AI가 꺼져도 결과가 나온다.** 모든 하네스는 `off` 상태의 대안(템플릿 + 데이터)을 가진다.
9. **주류 준수 기준을 공통 금지어로 쓴다.** 효능·건강 표현, 음주 권장, 미성년자 대상 표현 금지 (세부 기준 확인 필요).

### 검수 판정 3등급 (모든 하네스 공통)
| 등급 | 기준 | 조치 |
|---|---|---|
| 치명 | 틀린 숫자, 근거 없는 주장, 금지 표현, 개인정보 노출 | 작성 단계로 되돌림 + 대표 알림 |
| 주의 | 톤 불일치, 중복, 길이 초과, 형식 일부 위반 | 편집 단계에서 수정 |
| 참고 | 더 나은 표현 제안 | 대표 판단 |

## 5. 하네스 문서의 표준 구조

모든 하네스 문서는 아래 순서로 쓴다.

1. **목적과 위임 단계**
2. **역할** — 에이전트마다 이름, 맡은 일, 명세 6칸
3. **순서** — 무엇을 먼저, 무엇을 동시에
4. **넘김** — 단계별 파일 이름
5. **검수** — 통과 기준, 치명·주의·참고, 되돌릴 조건
6. **실행** — 명령, 입력값, 데이터 등급, provider
7. **AI off 대안**
8. **변경 기록** — 버전, 날짜, 무엇을 바꿨나

## 6. 실행 방법과 버전 관리

- **실행:** `kings run H02 FG-BS-375` 형식의 짧은 명령 하나 (AI 연결부를 거쳐 cloud/local 선택). 진행 확인은 `kings status`.
  ※ 실행 프로그램은 3단계(고급) 구축 과제이며, 그전에는 하네스 문서를 AI에게 그대로 주고 단계별로 진행한다.
- **기록:** 실행마다 `harness_runs`에 한 줄.
- **버전:** 분기마다 되돌림이 많았던 하네스부터 고친다. 문서 맨 아래 변경 기록에 남긴다.
- **비용:** 월 AI 예산을 정하고, 하네스별 비용을 월 결산(H04)에 표시한다.
