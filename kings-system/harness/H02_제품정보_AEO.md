# H02 · 제품 정보·AEO 하네스

## 1. 목적과 위임 단계
- 목적: SKU 하나에 대해 **사람용 소개**와 **AI가 읽는 제품 사양·FAQ**를 함께 만들고, 데이터베이스와 한 글자도 다르지 않게 검증한다
- 위임 단계: **3** (AI가 실행, 대표가 중간 점검)
- 대표만 하는 일: 감성 카피의 최종 톤, 공개 여부 결정

## 2. 역할

| 역할 | 맡은 일 | 명세 6칸 요약 |
|---|---|---|
| **B1 자료 정리자** (규칙 프로그램) | DB에서 SKU·병입로트·검사·수상 정보를 뽑아 사양표 원본을 만든다 | AI 아님. 숫자의 유일한 출처 |
| **B2 사양 작성자** | 사양표를 AI가 읽기 좋은 **항목-값 표**와 요약 문장으로 정리 | 목표: 비교 가능한 사양 / 형식: 표 12~15줄 + 3문장 요약 / 조건: B1에 없는 값 금지 |
| **B3 FAQ 작성자** | 루프 질문 지도에서 이 SKU에 해당하는 질문 8~10개에 답 | 맥락: 질문하는 사람과 그 사람의 AI / 형식: 질문-답(2~3문장) / 기준: 답마다 근거 항목 표시 |
| **B4 사람용 카피 작성자** | 상세페이지 상단 감성 소개 3종 (30자·100자·300자) + **5단계 판매 글**(후킹→가치 입증→라포→증거→행동 유도) | 자료: 브랜드 각본, 문장 은행, **고객 의심 목록**(docs/16) / 조건: 효능·과장 금지 / 기준: 의심 10개 모두에 답했는가 |
| **B5 검사자** | DB 대조, 금지어, AI 가독성 점검 | **B2~B4와 다른 AI** / 기준은 5장 |

## 3. 순서
```
B1 자료 정리(규칙) ─▶ B2 사양 ─┐
                    ├▶ B3 FAQ ─┼─▶ B5 검사 ─▶ 대표 확인 ─▶ 공개 (A1 공식 정보)
                    └▶ B4 카피 ─┘      │
                         ▲─── 치명 시 되돌림 ┘
```

## 4. 넘김 (파일)
`01_DB사양원본.json` → `02_사양표.md` / `03_FAQ.md` / `04_카피.md` → `05_검사보고서.md` → `06_공개본.md`

## 5. 검수
| 기준 | 판정 |
|---|---|
| 표·FAQ·카피의 숫자가 DB 원본과 다르다 | 치명 |
| 효능·건강·음주 권장·미성년자 관련 표현 | 치명 |
| 원료 원산지·주종 표기가 원본과 다르다 | 치명 |
| 사양표에 비교 가능한 수치 항목이 10개 미만 | 주의 |
| FAQ 답에 근거 항목 표시가 없다 | 주의 |
| 표가 아닌 문단으로만 되어 있다 (AI 가독성) | 주의 |

### 사양표 필수 항목 (봉신설주 예)
제품명 / 주종 / 원료와 원산지(산돌배·쌀 등) / 알코올 도수 / 용량 / 증류 방식 / 숙성 용기·기간 / 생산지 / 제조사 / 병입로트 공개 방식 / 보관 방법 / 추천 음용법·페어링 / 선물 포장 여부 / 인증·수상 / 가격대

## 6. 실행
- 명령: `kings run H02 FG-BS-375`
- 트리거: 새 병입로트, 가격·사양 변경, 분기 FAQ 갱신
- 데이터 등급: 공개 (원가·레시피 제외)
- provider: cloud 기본

## 7. AI off 대안
B1 사양 원본을 정해진 표 양식에 그대로 넣는다 (규칙). FAQ는 기존 FAQ에서 해당 질문을 고른다. 카피는 문장 은행 사용.
