# 분석 노트 — 위임의 시대 · AI 간택의 경제 · 막히기 시작

> 자료: 김덕진(IT커뮤니케이션연구소) 『AI 2027 트렌드&활용백과』 강의 슬라이드 (대표 제공, 2026.11)
> 사례·수치는 강의 자료 기준이며 원문 확인은 각 출처를 따른다.
> 목적: **대표가 왜 AI가 필요하다고 느끼는지, 왜 비전을 말하는지, 왜 대안을 찾는지**를 하나의 논리로 정리하고 킹스양조장 설계에 반영한다.

---

## 1. 결론부터 — 세 가지 질문은 하나의 논리다

```
[필요] 1인은 위임하지 못하면 성장하지 못하고, 고객은 이제 AI에게 묻는다
   ↓
[위험] 그런데 AI의 입구는 이미 막히기 시작했다 (정부보다 플랫폼이 먼저)
   ↓
[비전] 모델·플랫폼은 바뀐다 → 바뀌지 않는 '내 기준·내 데이터·내 하네스'를 가진 대표가 이긴다
   ↓
[대안] 입구를 여러 개로, 하네스는 내 손에, 막혀도 도는 규칙 시스템
```

대표가 느낀 불안은 막연한 두려움이 아니라 **정확한 전략적 직감**이었다. 다만 막힘의 1차 형태는 '정부 규제'보다 **플랫폼의 문지기 행동**으로 먼저 오고 있다.

## 2. 왜 AI가 필요한가 — 두 개의 생존 이유

### 2-1. 위임의 격차 (안쪽: 일하는 방식)
- 2027년의 격차는 "AI를 쓰느냐"가 아니라 **"얼마나 맡겼느냐"**, 그리고 **팀장처럼 쓰느냐, 검색창처럼 쓰느냐**에서 벌어진다.
- 6차산업 1인 대표는 64개 업무를 혼자 한다. 위임하지 못하면 대표의 시간이 곧 회사의 한계다.
- 사람의 일은 **'실행'에서 '방향 설정·기준·평가'로** 옮겨 간다. 혼자 일하지만 작은 AI 팀을 거느리는 **에이전트 보스**가 된다.

### 2-2. AI 간택의 경제 (바깥쪽: 팔리는 방식)
- 고객이 선택을 AI에게 맡기는 순간, **설득할 상대는 고객이 아니라 고객의 AI**다 (운전기사 경제).
- AI의 답변에는 2페이지가 없다. 수천 개 후보 중 3~4개만 보여준다. 목록에 없으면 **투명 브랜드**다.
- 반대로 **광고비를 거의 쓰지 못하는 작은 양조장도 AI에게 잘 보이면 판을 뒤집는다.**
  → 킹스양조장에게 이것은 위협이자 **가장 큰 기회**다. 대기업 광고비와 싸우지 않아도 된다.

> **정리:** AI는 1인 기업에게 '편리한 도구'가 아니라 **안쪽(위임)과 바깥쪽(간택) 모두에서 생존 조건**이 되었다.

## 3. 왜 비전을 말하는가 — 도구는 낡고, 기준은 남는다

| 사실 | 의미 |
|---|---|
| 모델은 몇 달마다 갈아탄다 | 특정 AI 사용법 숙련은 금방 낡는다 |
| 결과는 **내 데이터와 규칙**에서 갈린다 | 경쟁력은 모델이 아니라 **하네스**(AI용 업무 매뉴얼)에 있다 |
| 하네스는 코드가 아니라 **말로 쓴 문서**다 | 개발자가 아니어도 대표가 직접 만들 수 있다 |
| 검증이 산업이 된다 | "그럴듯하면 끝"인 회사와 기준을 가진 회사가 갈린다 |

**비전이란, 모델을 갈아타도 변하지 않는 우리 회사의 방향과 기준이다.**
킹스양조장이 지금까지 설계한 회사 헌법·SOP·문장 은행·데이터베이스·로트 기록은 모두 **하네스의 원재료**다. 이것이 대표가 비전을 말해야 하는 실무적 이유다.

## 4. 왜 대안을 찾는가 — 막힘은 이미 시작됐다

### 4-1. 강의 자료의 사례
| 사례 | 일어난 일 | 교훈 |
|---|---|---|
| 카카오톡 연동 AI 비서 | 카톡 대화방을 읽고 대신 보내는 기능을 열었다가 하루 만에 중단 (플랫폼과 사전 협의 없이 연 기능으로 알려짐) | **남의 플랫폼 위에 지은 자동화는 하루 만에 사라질 수 있다** |
| 아마존 | 외부 쇼핑 에이전트 차단, "주요 쇼핑 에이전트는 자사 AI" | 1등은 문을 닫고 자기 AI만 쓰게 한다 |
| 이베이 | 허락 없는 대리 구매 금지, 결제는 사람만 | 결제·인증이 관문이 된다 |
| 월마트·쇼피파이 | 한도·승인·카드 비공개 조건으로 외부 AI 비서에 입구를 연다 | 2·3등은 문을 열어 손님을 끈다 |
| 미국 법원 | "접근한 건 사용자" — AI 에이전트 차단 가처분 취소 | 규칙은 아직 정해지는 중 |

**패턴: 1등은 막고, 2·3등은 연다.** 한국도 같은 그림이 될 가능성이 크다 (매일 쓰는 앱 — 카카오톡·네이버 — 안의 '맡기는 기능'이 위임의 첫 입구가 된다).

### 4-2. 킹스양조장이 받는 영향
| 막힘의 형태 | 킹스양조장 위험 | 대안 |
|---|---|---|
| 플랫폼이 외부 AI 연동을 막음 | 카톡·스마트스토어 등에 붙인 자동화가 갑자기 멈춤 | 핵심 자동화는 **내 PC·내 DB**에, 플랫폼은 '엑셀 내려받기' 같은 최소 연결만 |
| 플랫폼 자체 AI만 허용 | 그 플랫폼 AI의 추천 목록에 들어가야 함 | 플랫폼별 상품 정보도 **AI가 읽는 형식**으로 |
| 결제·신원인증 관문 | 주류는 성인 인증이 필수 → AI 대리 결제는 늦게 열릴 가능성 (판단) | AI는 **발견·추천** 단계에 집중, 결제는 사람이 하는 자사몰·스마트스토어로 |
| 클라우드 AI 요금·정책 변화 | 꺼지지 않는 AI가 기본값이 되면 토큰 청구서가 커짐 | 규칙 자동화 우선, 로컬 AI, 사용량 계기판 |
| 정부 규제 | 기존 설계대로 | AI 연결부 cloud → local → off |

> **정리:** 대안을 찾는 이유는 AI를 덜 쓰기 위해서가 아니라, **어느 입구가 닫혀도 회사가 계속 보이고, 계속 일하게** 하기 위해서다.

## 5. 킹스양조장 설계에 반영할 것

### 5-1. 명세 6칸 — AI 업무 지시서 표준
결과가 이상하면 모델을 탓하기 전에 **빠진 칸**부터 찾는다.

| 칸 | 빠지면 | 킹스 예시 (봉신설주 상세페이지 제품 정보) |
|---|---|---|
| ① 목표 | 가장 흔한 용도를 가정 | 스마트스토어 상세페이지 하단 '제품 정보' 표 |
| ② 맥락 | 평균 독자를 상정 | 읽는 사람: 명절 선물을 찾는 40~60대, 그리고 **그 고객의 AI** |
| ③ 자료 | 그럴듯한 내용을 지어냄 | 제품 마스터(원료·도수·용량·숙성), 검사 성적서, 수상 이력만 사용 |
| ④ 조건 | 범위를 넘고 장황해짐 | 효능·건강 표현 금지, 과장 금지, 자료에 없는 수치 금지 |
| ⑤ 형식 | 매번 모양이 다름 | 항목-값 표 12줄 + FAQ 8개 |
| ⑥ 기준 | '그럴듯하면 끝' | 모든 수치는 마스터와 일치, 모르면 "확인 필요"로 표시 |

### 5-2. 협업 4단계 — 64개 업무를 몇 단계에 둘 것인가
**어느 업무를 몇 단계에 둘지 정하는 것이 대표의 일이다.** 그리고 가장 안전한 위임처는 AI가 아니라 **규칙 프로그램**이다.

| 단계 | 정의 | 킹스양조장 업무 예 |
|---|---|---|
| 규칙 | AI 아님, 계산·집계 프로그램 | 재고 차감, 원가 계산, 주세 집계, 세무 일정 알림, 백업 |
| 1 | 사람 실행, AI 보조 | **맛 결정·블렌딩**, 가격 정책, 레시피 변경 (영구히 1단계) |
| 2 | 사람 실행, AI 옆에서 지원 | 지원사업 계획서, 바이어 협상, 브랜드 각본 |
| 3 (에이전트) | AI 실행, 사람 중간 점검 | 상세페이지·제품 정보, CS 1차 답변, 공고 탐색·요약, 월 결산 해설 |
| 4 (에이전트) | AI 실행, 사람 최종 승인 | 재구매 안내 초안 발송 대기열, 발효 이상 알림 해석, 증빙 분류 |

### 5-3. 에이전트 팀과 배관 — 킹스양조장 구조도
```
                     [대표 = 에이전트 보스]  무엇을 어디까지 맡길지 정하고 검수한다
          ┌──────────────┬──────────────┬──────────────┐
   [리서치 에이전트]  [문서 에이전트]   [판매 에이전트]   [운영 = 규칙 프로그램]
   공고·시장·트렌드   서류·상세·번역    안내·CS·제안서    재고·원가·주세·알림
          └──────────────┴──── 배관(연결 표준, 예: MCP) ────┴──────────────┘
      kings.db(데이터) · KINGS 폴더(문서) · 캘린더·메일 · 스마트스토어 엑셀
```
- 배관은 **내 데이터 쪽에 둔다.** 플랫폼이 막아도 데이터와 하네스는 남는다.

### 5-4. 킹스 하네스 — 우선 3개
하네스 5부품: **역할 · 순서 · 넘김 · 검수 · 실행 버튼**. 모두 말로 쓴 문서다. **만드는 AI와 검사하는 AI를 가른다.**

| 하네스 | 역할 | 순서 | 검수 기준 |
|---|---|---|---|
| ① 지원사업 서류 | 공고 분석가, 작성자, 평가위원 관점 검토자, 숫자 검증자 | 분석 → 작성 → 검토 → 검증 → 대표 확인 | 평가항목 대응, 숫자는 DB와 일치, 과장 없음 |
| ② 제품 정보·상세페이지 (AEO) | 자료 정리자, 작성자, AI 가독성 검사자 | 마스터 → 표·FAQ → 검사 → 대표 확인 | 모든 수치 출처, 금지어, 표·FAQ 구조 |
| ③ 월간 경영 보고 | 집계(규칙 프로그램), 해설자, 이상 탐지자 | 집계 → 해설 → 이상 표시 → 대표 확인 | 숫자는 프로그램 값만 사용 |

### 5-5. AEO — 고객의 AI에게 보이기
**AI는 사진이 아니라 글자를 본다.** 사람이 거의 보지 않는 한 줄이 AI의 선택을 결정한다.

| 사람용 카피 (그대로 둔다) | AI용 글자 (새로 더한다) |
|---|---|
| "돌배의 향을 품은 깊은 한 잔" | 원료: 산돌배·쌀 / 주종 / 도수 41% / 375ml / 증류 방식 / 숙성 용기·기간 / 생산 지역 / 배치 번호 공개 / 수상·인증 |

- **로그인 없이 열리는 곳 4가지**를 갖춘다: 회사 소개 · 제품 사양 · FAQ · 공식 입장
- **퍼널이 멈추고 루프가 돈다:** 상황별 질문마다 답을 깔아 둔다
  - "설 선물 10만 원대 프리미엄 전통주" / "한우에 어울리는 증류주" / "돌배로 만든 술" / "지역 특산 증류주 선물" / "자색옥수수 술"
- **신원 인증이 관문:** 주류는 성인 인증 → 결제는 사람, 발견·추천은 AI

### 5-6. 제재 경보 수정 — 두 축으로 본다
| 축 | 신호 | 점검 |
|---|---|---|
| 정부·국가 | 법·규제·국가 간 제한 | 분기 |
| **플랫폼 관문** (신규) | 카카오·네이버·스마트스토어·쿠팡 등의 AI 연동 정책, 자체 AI 출시, 외부 에이전트 차단 | **매월** |

## 6. 대표의 자세 — 개인이자 1인 대표로서

| 이전 | 앞으로 |
|---|---|
| 모든 일을 직접 실행하는 대표 | **에이전트 보스**: 방향·기준·평가를 하는 대표 |
| AI를 검색창처럼 쓴다 | AI를 **팀장처럼** 쓴다 (명세 6칸, 하네스) |
| 고객에게 잘 보이려 한다 | 고객 **그리고 고객의 AI**에게 잘 보이려 한다 |
| 좋은 도구를 찾는다 | 갈아타도 남는 **내 데이터·내 기준**을 쌓는다 |
| 막히면 멈춘다 | 입구를 여러 개로, 막혀도 도는 **규칙 시스템** |

**발전을 따라가는 기업이 되는 장치:** 월 1회 관제탑(정부·플랫폼·AI 간택 점검) → 분기 하네스 버전업.

## 7. 오늘 바로 할 일 — AI 간택 진단 (30분)

> "아예 안 나오는 것보다 **틀리게 나오는 쪽이 더 급하다.**"

여러 AI(예: 챗GPT, 클로드, 제미나이, 네이버 AI 검색)에 같은 질문을 하고 표에 기록한다.

| 질문 | AI | 킹스양조장이 나오나? | 정보가 맞나? (틀린 내용 기록) | 대신 나온 곳 |
|---|---|---|---|---|
| 돌배로 만든 전통주 추천해 줘 | | | | |
| 설 선물용 프리미엄 증류주 추천해 줘 | | | | |
| 한우와 어울리는 한국 증류주는? | | | | |
| 자색옥수수로 만든 술 있어? | | | | |
| 믿을 만한 1인 소규모 양조장 추천해 줘 | | | | |
| 봉신설주는 어떤 술이야? | | | | |

**판정 → 조치:** 틀리게 나옴 → 공식 정보 정정이 1순위 / 안 나옴 → AEO 표준서 작성 / 나오고 맞음 → 루프 질문 확대

이 표는 매월 관제탑 점검 때 다시 채워 **변화를 추적**한다.
