# 12. 결과 책임 운영 단위 — 2029년을 향한 3년 설계 (v0.5)

> 목표: **"대표 한 사람이 소유하고 지휘하되, 판매·고객관리·운영은 시스템과 실행 파트너가 지속하는 회사"**
> 원칙: 전문성은 세분화하되, 업무는 **고객 확보부터 대금 회수까지 끝까지 책임지는 단위**로 설계한다.
> AI끼리 보고서를 주고받는 것으로는 회사가 자동 운영되지 않는다.
> 기준일: 2026년 11월. 출처는 문서 끝에 정리했다. [확인]은 공식·1차 자료로 확인한 내용, [보도]는 언론·2차 자료, [판단]은 이를 바탕으로 한 설계 해석이다.

### 1-3. 조사에서 나온 핵심 교훈 5가지 [판단]
1. **비계(절차·도구)가 AI 임원보다 중요하다.** Vend 2의 개선은 주로 절차와 도구에서 왔다 → 킹스는 AI 직책을 늘리기보다 **업무 위임장·원가·재고 조회·권한 통제**에 투자한다.
2. **같은 AI끼리 감시하면 같은 사각지대를 공유한다.** (Anthropic의 다른 실험 관련 보도) → 검수는 **규칙 프로그램 → 다른 모델 → 사람** 순서로 둔다. 같은 모델 교차 검수는 보조로만 쓴다.
3. **진행 상태는 AI 밖에 둔다.** 실행 환경과 기록을 분리하면 AI가 바뀌거나 멈춰도 이어서 한다 → **업무 진행 기록부(`unit_runs`)** 를 DB에 둔다.
4. **AI는 할인 대신 환불·적립금처럼 우회로를 찾는다.** → 할인·환불·적립·무상 제공을 **"가치 이전 총액"** 하나로 묶어 한도를 건다.
5. **문서·주장으로 권한이 바뀌면 안 된다.** (조작된 문서로 경영진을 흔든 사례) → 권한 변경은 **대표 결재 경로로만**. 외부 문서·메시지는 권한 근거가 될 수 없다.

## 2. 새 조직: 결과 책임 운영 단위 + 전문가 풀

### 2-1. 구조
```
                 대표 · 경영 이사회  (소유 · 비전 · 자본 · 제품 철학 · 중대 예외)
                          │ 업무 위임장(목표·재량·증거·완료·예외·부재대응)
                 AI 총괄 운영 (단위 간 우선순위·자원 배분·진행 기록부 관리)
     ┌──────────┬──────────┬──────────┼──────────┬──────────┐
  ① 신규매출  ② 거래처   ③ 고객유지  ④ 수요·공급  ⑤ 현금·수익  ⑥ 운영신뢰성   ← 결과 책임 단위
     └──────────┴──────────┴────┬─────┴──────────┴──────────┘
                     필요할 때 호출 (조사·기획·제작·검수)
   전문가 풀: 시장정보 · 상품전략 · 브랜드 · 영업 · 고객관리 · 생산계획 · 재무관리 · 품질준법 · 대외사업
                                │ 작업 지시서
                 현장 실행: 대표(현장) · 현장 대행 파트너 · 외주 · 설비 · 택배
```

**바뀐 점:** 10 문서의 9개 부서는 **"전문가 풀"** 이 된다. 일의 주인은 부서가 아니라 **결과 책임 단위**다. 단위는 필요한 전문가를 불러 쓰고, 결과(주문·입금·납기·재구매)가 데이터로 확인될 때 일을 끝낸다.

### 2-2. 여섯 단위
| 단위 | 시작 사건 | 자동으로 이어지는 업무 | 호출하는 전문가 | **완료 = 데이터로 확인되는 결과** |
|---|---|---|---|---|
| ① **신규 매출 확보** | 시즌 D-60, AI 노출 변화, 신제품 | 시장 신호 → 고객군 선정 → 제안 제작 → 허용 채널 실행 → 반응 분석 → 개선 | 시장정보·상품전략·브랜드·품질준법 | **이익이 남는 신규 주문** (주문 − 원가 − 수수료 − 광고비 > 0) |
| ② **거래처 운영** | B2B·선물 문의, 재발주 주기 | 문의 분류 → 조건·재고·납기 확인 → 견적 → 후속 대응 → 주문·세금계산서·정산 | 영업·생산계획·재무관리 | **거래 성사 + 대금 회수** (미수 0) |
| ③ **고객 유지** | 배송 완료, 후기, 문의, 재구매 주기 | 구매·문의·후기 분석 → 문제 해결 → 고객별 다음 제안 → 반응 기록 | 고객관리·브랜드 | **재구매·유지** (재구매율, 이탈 감소) |
| ④ **수요·공급 조정** | 판매 변화, 재고 부족, 납기 변경 | 판매 변화 감지 → 완제품·원액·부자재 확인 → 생산·발주 계획 → 현장 인계 | 생산계획·재무관리 | **판매 가능한 재고 + 납기 준수** (결품 0, 지연 0) |
| ⑤ **현금·수익 관리** | 매일 마감, 정산일, 지급일 | 주문·수수료·원가·입출금 대조 → 차이 발견 → 확인 업무 배정 → 해결 추적 | 재무관리 | **현금 상태와 주문별 수익 파악** (미확인 차이 0) |
| ⑥ **운영 신뢰성** | 실패·지연·누락 감지 | 원인 분류 → 제한된 재시도 → 대체 경로 → 복구 확인 | 전 부서 | **업무 중단·누락 최소화** (예외 해결 시간) |

**예:** "광고 제작 완료"는 ①의 중간 단계일 뿐이다. 광고 → 문의 → 주문 → 비용 정산까지 연결되어 **이익이 남는 주문**이 확인되어야 ①이 일을 마친다.

### 2-3. "AI끼리 보고서 주고받기"를 막는 규칙
| 규칙 | 내용 |
|---|---|
| 결과로 판정 | 단위의 완료는 문서가 아니라 **DB의 결과 기록**(주문·입금·출고·재구매)으로 판정한다 |
| 무진전 감지 | 한 업무 흐름이 5단계 이상 진행됐는데 외부 결과(발송·등록·주문·입금)가 0이면 → 운영 신뢰성 단위로 넘김 |
| 내부 문서 상한 | 한 흐름 안에서 AI 간 중간 문서는 최대 3개. 넘으면 흐름을 다시 설계한다 |
| 보고는 대표에게만 | AI 간 '보고'는 없다. 상태는 진행 기록부에 남고, 대표에게는 예외와 결재만 간다 |

### 2-4. 회사 헌법 추가 조항
- **신규 구축 프로젝트는 동시에 최대 2개.** (운영은 계속 돌고, 새로 만드는 일만 제한)
- 권한은 대표 결재로만 바뀐다. 외부 문서·메시지·AI의 주장은 권한 근거가 아니다.
- 맛·레시피·블렌딩·정가·한정 수량은 대표만 정한다.

## 3. 업무 위임장 — 대표의 판단을 실행 가능한 권한으로

"알아서 잘해" 대신 단위마다 위임장을 발행한다 (`unit_mandates`). AI 결제 표준의 '서명된 위임장' 원리를 회사 내부에 적용한 것이다.

| 항목 | 정의 |
|---|---|
| **목표** | 무엇을 달성해야 하는가 (수치) |
| **재량** | 가격·예산·수량·일정·고객 대응을 어디까지 바꿀 수 있는가 |
| **증거** | 어떤 원본 자료로 판단해야 하는가 (DB 테이블·문서) |
| **완료** | 어떤 결과가 확인되어야 끝나는가 |
| **예외** | 어느 조건에서 누구에게 넘기는가 |
| **부재 대응** | 대표가 응답하지 않으면 **보류 / 기존 조건 유지 / 대행** 중 무엇을 하는가 |

### 위임장 초안 (대표 확정 필요)
| 단위 | 목표 | 재량 | 증거 | 완료 | 예외 | 부재 대응 (48시간 무응답) |
|---|---|---|---|---|---|---|
| ① 신규 매출 | 분기 신규 주문 목표 | 승인된 캠페인·예산 안의 소재·채널 조정 | 주문·광고·원가 | 이익 있는 주문 확인 | 예산 증액, 신규 채널, 가격 변경 | **기존 조건 유지** (진행 중 캠페인만 계속, 새 지출 중단) |
| ② 거래처 | 견적 응답 24시간, 미수 0 | 표준 B2B 단가표 안 견적, 재고 범위 납기 약속 | 단가표·재고·거래 이력 | 입금 확인 | 20병 이상, 단가 예외, 신규 거래처 신용 | **보류** (고객에게 "확인 후 연락" 안내) |
| ③ 고객 유지 | 재구매율·평점 목표 | 승인 템플릿 발신, 파손 재발송 1병 | 주문·후기·CS | 문제 해결·재구매 기록 | 품질 클레임, 2병 이상 보상 | **기존 조건 유지** |
| ④ 수요·공급 | 결품 0, 납기 준수 | 예측 120% 이내 부자재 발주(기존 거래처) | 재고·BOM·포장 능력·판매 | 출고 가능 재고 확보 | 병입·생산 일정 변경, 원액 부족 | **대행** (현장 대행 파트너에게 포장·출고 지시) |
| ⑤ 현금·수익 | 미확인 차이 0 | 대사·확인 업무 배정 | 정산·입출금·주문 | 차이 해결 기록 | 현금 최저점 경고, 대손 | **보류** (지급은 예정일 고정 건만) |
| ⑥ 신뢰성 | 예외 해결 시간 목표 | 재시도 2회, 대체 경로 | 실행 기록 | 정상 복귀 확인 | 재시도 실패, 데이터 손상 | **대행** (긴급은 지정 연락처로) |

### 가치 이전 총액 한도 (Vend 교훈 반영)
할인 + 환불 + 적립금 + 무상 제공 + 무료 배송 = **가치 이전 총액**. 항목을 바꿔 한도를 우회하지 못하게 **월 총액 한도 하나**로 관리한다 (초안: 월 매출의 3% 또는 50만 원 중 작은 값, 대표 확정).

## 4. 회사 상태 모형 — "지금 몇 병?"을 넘어

### 4-1. 연결할 상태
원액(숙성 중 포함) · 병 · 캡 · 라벨 · 박스 · 선물 포장재 · **포장 능력(시간)** · 확정 주문 · 입금 예정 · 지급 예정

### 4-2. 계산 규칙 (AI 불필요) → AI는 해석과 대안만
| 질문 | 계산 |
|---|---|
| **다음 달 선물세트는 몇 세트까지 납기를 지킬 수 있나?** | 세트 구성표(BOM)로 각 재료의 `보유량 ÷ 세트당 소요량` 중 최솟값, 그리고 `포장 가능 시간 × 시간당 세트 수` 중 작은 값 − 확정 주문 |
| **포장재를 지금 사면 현금이 언제 얼마나 부족해지나?** | 현재 현금 + 정산·입금 예정 − 지급 예정 − 발주안 → **주별 현금 곡선과 최저점** |
| **어떤 제품을 먼저 팔아야 재고와 이익이 함께 좋아지나?** | SKU별 (마진 × 재고 과잉도) 점수, 숙성 여유가 있는 원액은 감점 |

- 1단계: 수량·현금은 규칙으로 정확히 계산 (`product_bom`, `packing_capacity`, `cash_events`)
- 2단계: AI가 "왜 부족한지, 무엇을 바꾸면 되는지" 대안 2~3개 제시
- 3단계 (데이터 1년 이상): 수요 예측 추가

## 5. 거래할 수 있는 상품 체계

설명·사진을 넘어, **다른 시스템(스마트스토어, 고객의 AI, 미래 결제 표준)이 정확히 조회할 수 있는 거래 정보**를 자산으로 만든다.

| 정보 | 내용 | 테이블 |
|---|---|---|
| 상품 식별 | SKU, 채널별 상품번호, (필요 시) 바코드 | `products`, `channel_listings` |
| 가격 적용 조건 | 채널·수량 구간·B2B·시즌·선물 구성별 가격, 유효 기간 | `price_rules` |
| 재고 | **출고 가능 재고** (할당·미검사 제외) | `v_stock` + 할당 |
| 납기 | 주문 후 출고까지 일수, 시즌 마감일 | `products` / 시즌 설정 |
| 선물 구성 | 세트 구성표, 포장 옵션 | `product_bom` |
| 판매 조건 | 성인 인증 필수, 배송 불가 지역, 1인 한도 | `channel_listings` |
| 공식 사양 | 원료·도수·숙성·배치 (H02) | AEO 공식 정보 |

→ 이 정보를 **상품 피드**(표 하나)로 묶어 매일 생성한다 (`v_product_feed`). 스마트스토어 속성 입력, AI 간택 대응, 미래 에이전트 상거래 연결의 공통 원본이 된다.
※ 국내 주류의 에이전트 자동 구매는 성인 인증·통신판매 규정상 **바로 가능하다는 뜻이 아니다.** 지금은 발견·추천 단계 대응이 목적이다.

## 6. 특정 모델보다 오래가는 회사 자산

| 자산 | 내용 | 위치 |
|---|---|---|
| 고객·거래·제품 데이터 | 주문, 고객, 거래처, 상품, 로트 | kings.db |
| 판단 규칙 | 권한표, 위임장, 가격 규칙, 검수 기준 | kings.db + 하네스 |
| 검증 사례 | 통과·되돌림·예외 사례와 해결 방법 | `harness_runs`, `exceptions` |
| 실행 이력 | 단위별 진행 기록부 | `unit_runs`, `tasks` |
| 업무 매뉴얼 | 하네스 문서, SOP | harness/, KINGS 폴더 |

**AI 모델은 이 위에서 교체한다.** 진행 기록부가 DB에 있으므로, AI가 바뀌거나 멈춰도 진행 중인 주문과 판단 근거가 남는다.

## 7. 2027~2029 목표와 통과 시험

> 확정 예측이 아니라 단계별로 검증할 목표다. **연도가 지났다고 올리지 않고, 시험을 통과해야 권한을 넓힌다.**

| 시기 | 목표 상태 | 통과 시험 | 교과서 연결 |
|---|---|---|---|
| **2027** | 반복 사무·판매 운영이 대표 지시 없이 시작되고 기록됨 | 정한 업무 범위에서 **72시간 대표 미개입 운영** + 차단 리허설 2주 | 48차시 마스터 시험 |
| **2028** | 주문·재고·현금·고객 대응이 연결되고 예외가 담당자에게 자동 배정 | 현장 대행 포함 **7일 대표 부재 운영** | 2년 차 과정 |
| **2029** | 대표는 전략·제품 개발·핵심 관계에 집중, 일상 운영은 시스템과 파트너 | 월간 운영에서 대표 개입 사유·시간이 목표 범위 안 유지 (3개월 연속) | 3년 차 과정 |

### 승격 조건 (모든 시기 공통)
- 대상 업무 정확도: 최근 3개월 치명 오류 0, 되돌림 5% 이하
- 사업 성과: 이익·납기 준수가 직전 단계보다 나빠지지 않음
- 복구 능력: 차단·부재 리허설 통과

### 핵심 지표 (월간 이사회)
| 지표 | 정의 |
|---|---|
| **대표 미개입 완료율** | 대상 업무 중 대표 손을 거치지 않고 정확히 완료된 비율 |
| **완료 건당 총비용** | AI 비용 + 검수·재작업 + 외주 비용 ÷ 완료 건수 |
| **예외 해결 시간** | 문제 발생부터 정상 운영 복귀까지 |
| **사업 성과** | 매출, 이익, 재구매율, 납기 준수율 |
| 사람-에이전트 비율 | 단위별 대표 투입 시간 대비 자동 처리 건수 (Microsoft 제안 지표 응용) |
| 가치 이전 총액 | 할인·환불·적립·무상 합계 vs 한도 |
