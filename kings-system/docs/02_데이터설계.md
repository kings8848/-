# 02. 데이터 설계

## 1. ID(번호) 체계

번호만 보고 무엇인지 알 수 있게 만든다. 모든 번호는 시스템이 자동 발행한다.

| 대상 | 형식 | 예시 | 비고 |
|---|---|---|---|
| 품목코드 | `분류-약칭-일련` | `RM-DB-01` 돌배, `RM-PC-01` 자색옥수수, `PK-BT-375` 375ml 병, `FG-BS-375` 봉신설주 375ml | RM 원료 / PK 부자재 / WIP 반제품 / FG 완제품 / AG 농자재 |
| 필지 | `FD-일련` | `FD-01` | |
| 수확로트 | `H-연도-작물-일련` | `H-26-DB-03` | 자가 수확분 |
| 원료로트 | `R-연월일-일련` | `R-261117-01` | 자가 수확분도 입고 시 원료로트로 전환 |
| 담금배치 | `B-제품-연월-일련` | `B-BS-2611-01` | 제품: BS 봉신설주, DB 돌배주, PC 자색옥수수주, LT 한정판 |
| 증류 | `D-배치번호-회차` | `D-BS-2611-01-1` | 1차·2차 증류 구분 |
| 숙성 | `A-용기-시작연월` | `A-OK03-2611` | 용기: OK 옹기, OB 오크통, ST 스테인리스 |
| 블렌드 | `BL-연월일-일련` | `BL-270301-01` | |
| 병입로트 | `L-제품-연월일-일련` | `L-BS-270315-01` | **라벨 Batch No.로 인쇄** |
| 주문 | `O-연월일-일련` | `O-261117-005` | |
| 고객 | `C-일련` | `C-00128` | |
| 거래처 | `P-일련` | `P-012` | 공급처·거래처·농가·기관 공통 |
| 비용 | `E-연월-일련` | `E-2611-034` | |
| 지원사업 | `G-연도-일련` | `G-26-02` | |

## 2. 로트 추적 사슬 (밭 → 고객)

```
FD-01 (필지)
  └ H-26-DB-03 (수확 320kg)
      └ R-261020-01 (원료 입고)
          └ B-BS-2611-01 (담금: R-261020-01 200kg + 쌀 R-261101-02 …)
              └ D-BS-2611-01-1, -2 (증류)
                  └ A-OK03-2611 (옹기 숙성 120일)
                      └ L-BS-270315-01 (병입 480병, 41%)
                          └ O-270320-011 → C-00128 (고객)
```

- **앞으로 추적:** 이 원료로트는 어떤 병들이 되었나? → 품질 문제 발생 시 회수 범위 확정
- **뒤로 추적:** 이 병은 어느 밭, 어느 날 수확한 원료인가? → 고객 클레임 대응, 배치 스토리(QR)

## 3. 핵심 구조: 수불 원장 하나로 모든 재고 관리

재고 숫자를 따로 적지 않는다. **모든 입·출을 한 장부(inventory_moves)에 +/−로 기록**하고, 재고는 합계로 계산한다.

| 발생 업무 | 원장 기록 (자동) |
|---|---|
| 원료 입고 | 원료 +200kg |
| 담금 투입 | 원료 −200kg |
| 병입 | 원액 −180L, 병 −480, 라벨 −480, 완제품 +480 |
| 출고 | 완제품 −6 |
| 시음·파손 | 완제품 −1 (사유 기록) |
| 월말 실사 | 차이만큼 조정 (사유 기록) |

→ 재고가 틀리면 원장을 보면 **언제, 왜** 틀렸는지 바로 보인다.

## 4. 테이블 구조 (요약)

전체 정의는 [`db/schema.sql`](../db/schema.sql) 참조.

### 마스터 (기준 정보, 가끔 변경)
| 테이블 | 내용 |
|---|---|
| items | 품목 (원료·부자재·반제품·완제품·농자재), 단위, 안전재고, 표준단가 |
| products | 판매 SKU (주종, 용량, 도수, 소매·도매가, 한정판 여부·수량) |
| partners | 공급처·거래처·농가·물류·기관 |
| customers | 고객 (성인 인증, 마케팅 동의, 등급) |
| fields | 필지 (위치, 면적, 작물, 주수) |
| vessels | 설비·용기 (발효조, 증류기, 옹기, 오크통, 용량) |
| recipes / recipe_lines | 레시피와 배합 (**영업비밀 — 로컬 전용**) |
| liquor_tax_rates | 주종별 주세 방식·세율 (세무사 확인 후 입력) |

### 1차 농업
| 테이블 | 내용 |
|---|---|
| farm_tasks | 작업일지 (전정·시비·방제 등, 자재 사용량, 작업시간) |
| harvests | 수확로트 (필지, 수량, 등급) |

### 2차 생산·품질
| 테이블 | 내용 |
|---|---|
| material_lots | 원료로트 (출처: 자가수확/매입, 단가, 검수) |
| batches / batch_inputs | 담금배치와 투입 원료 |
| ferment_logs | 발효 측정 (온도·당도·pH·알코올, 수기/센서) |
| distillations | 증류 (초류·본류·후류 용량과 도수, 에너지) |
| aging / aging_logs | 숙성 (용기, 기간, 손실, 관능) |
| blends / blend_lines | 블렌딩 |
| bottlings | 병입로트 |
| quality_checks | 품질 검사 결과 |

### 재고·판매·서비스
| 테이블 | 내용 |
|---|---|
| inventory_moves | **수불 원장** |
| orders / order_items | 주문과 품목 (병입로트까지 기록) |
| shipments | 출고 (주세 반출 대상 여부) |
| payments | 결제·정산 |
| cs_tickets | 고객 문의 |
| experiences | 체험·견학 예약 |

### 사무·세무
| 테이블 | 내용 |

## 5. 입력 원칙

| 원칙 | 내용 |
|---|---|
| 선택 입력 우선 | 품목·로트·설비는 목록에서 고른다 (오타 방지) |
| 필수값 최소화 | 현장 입력은 3~5개 항목만 필수 |
| 날짜·시간 자동 | 입력 시각 자동 기록, 필요하면 수정 |
| 단위 고정 | 원료 kg, 액체 L, 도수 %, 온도 ℃, 당도 °Bx, 병 개 |
| 수정 이력 | 기록은 지우지 않고 '취소' 또는 '조정' 기록을 추가 |
| 개인정보 | 고객 연락처는 판매·배송 목적만, 외부 AI에 입력 금지 |
