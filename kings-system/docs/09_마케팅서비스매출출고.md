## A. 마케팅 — 고객과 고객의 AI에게 보이기

### A1. AEO 공식 정보 4종 (로그인 없이 열리는 곳)
| 문서 | 내용 | 위치 | 처리 | 갱신 |
|---|---|---|---|---|
| 회사 소개 | 설립, 소재지, 대표, 6차산업 구조(자가 재배), 인증·수상 | 자사몰/블로그 공개 페이지 | H02 | 변경 시 |
| 제품 사양 | SKU별 원료·주종·도수·용량·증류 방식·숙성 용기와 기간·생산지·보관법·가격대·배치 번호 공개 여부 | 제품별 페이지, 스마트스토어 상세 하단 표 | H02 | 병입 로트 바뀔 때 |
| FAQ | 선물·페어링·보관·배송·성인 인증·대량 주문 질문 30개 | 공개 FAQ 페이지 | H02 | 분기 |
| 공식 입장 | 원료 원산지, AI 사용 원칙("서류는 AI가 돕고 술은 사람이 빚는다"), 정정 공지 | 공지 페이지 | 사람 | 필요 시 |

**규칙:** 모든 수치는 `products`·`bottlings`·`quality_checks`에서 가져온다. 데이터베이스와 다른 숫자가 공개되지 않게 한다.

### A2. 루프 질문 지도
고객이 AI에게 물을 법한 **상황별 질문**과 그에 대한 공식 답을 짝지어 관리한다 (`loop_questions` 테이블).

| 상황 | 질문 예 | 답을 둘 곳 | 연결 SKU |
|---|---|---|---|
| 명절 선물 | 설 선물 10만 원대 프리미엄 전통주 | FAQ, 선물세트 페이지 | 선물세트 |
| 페어링 | 한우와 어울리는 한국 증류주 | 페어링 가이드 | 봉신설주 |
| 원료 호기심 | 돌배로 만든 술 / 자색옥수수 술 | 제품 사양, 원료 이야기 | 해당 SKU |
| 지역 | ○○ 지역 특산주 추천 | 회사 소개, 제품 사양 | 전 제품 |
| 소장·한정 | 한정판 넘버링 전통주 | 한정판 페이지 | 한정판 |
| 기업 선물 | 기업 명절 선물 전통주 대량 | B2B 안내 페이지 | 선물세트 |

### A3. 콘텐츠 캘린더
| 채널 | 주기 | 내용 | 처리 | 단계 |
|---|---|---|---|---|
| 인스타그램·쇼츠 | 주 2회 | 제조 현장(실사진·실영상), 원료 계절 소식 | H05 초안 + **실촬영** | 3 |
| 블로그·스토리 | 월 2회 | 루프 질문에 답하는 글 (페어링, 선물 가이드) | H05 | 3 |
| 스마트스토어 소식 | 시즌·한정판 | 출시·사전예약 안내 | H05 | 3 |
| 카톡 채널 | 월 1회 + 시즌 | 동의 고객 대상 안내 | 규칙(대상 추출) + H05(문구) | 4 |

**진정성 규칙:** 제조 과정·원료·대표 사진은 실제 촬영만 쓴다. AI 이미지는 분위기 컷에만, 필요하면 표기한다.

### A6. AI 간택 진단 (매월, H06)

판정: 틀림 → 공식 정보 정정 1순위 / 안 나옴 → A1·A2 보강 / 맞음 → 질문 확대.

### A7. 주류 마케팅 준수 체크 (확인 필요)

## B. 서비스 — 경험을 다음 구매로

### B1. CS 처리 흐름
| 단계 | 처리 | 단계 |
|---|---|---|
| 수집 | 채널별 문의 → `cs_tickets` (스마트스토어·카톡·전화 메모) | 규칙 / 사람 |
| 분류 | 배송·파손·품질·선물·대량·교환반품·기타 (키워드 규칙 → 모호하면 H03) | 규칙 + H03 |
| 정보 결합 | 주문·송장·병입로트·검사 기록을 자동으로 붙인다 | 규칙 |
| 답변 초안 | 템플릿 + 데이터 → H03 다듬기 | 3 |
| 승인·발송 | 대표 확인 후 발송 (배송 문의는 검증 뒤 4단계로 승격) | 3→4 |
| 기록 | 처리 결과, 소요 시간, 재발 방지 메모 | 규칙 |

**응답 기준:** 영업일 24시간 이내 첫 답변. 품질·파손은 당일.

### B2. 후기 관리
| 상황 | 처리 |
|---|---|
| 배송 완료 D+3 | 후기 요청 메시지 (규칙) |
| 후기 등록 | 수집 → `reviews` → 평점 3 이하는 `issue_flag` → CS로 연결 |
| 답글 | H03 초안 → 대표 승인 (3) |
| 분석 | 월 1회 후기 키워드 요약 → 제품·포장 개선, FAQ 보강 (H04) |

### B3. 클레임·역추적
1. 병입로트 확인 → `v_trace_direct` + 다단계 추적(A-23)으로 원료·필지·공정 기록 출력
2. 같은 로트의 다른 출고 건과 검사 기록 확인
3. 대표 판단 (1단계) → 교환·환불·회수 범위 결정
4. 원인과 조치를 `cs_tickets.resolution`과 품질 기록에 남긴다

### B4. VIP·B2B 관리
| 대상 | 관리 |
|---|---|
| VIP 고객 | 한정판 우선 예약, 손글씨 카드(사람), 연 1회 감사 안내 |
| B2B 거래처 | 월 거래 현황, 미수금, 재발주 주기 알림, 신제품 샘플 |
| 기업 선물 | 전년 주문 기업에 시즌 D-45 제안 (H08) |

### B5. 체험·견학 운영
예약 → 전날 안내(규칙) → 시음 수량 차감(규칙) → 체험 후 고객 등록·동의 → D+7 감사·구매 안내.

### B6. 고객의 AI가 묻는 경우 대비
- FAQ·제품 사양을 **표와 문답 구조**로 공개 (A1)
- 문의 응대 규칙 문서(배송 기한, 교환 조건, 성인 인증)를 공개해, AI가 정확히 인용할 수 있게 한다
- 에이전트 결제는 주류 특성상 늦게 열릴 가능성 (판단) → 지금은 **발견·추천 단계 대응**에 집중

## C. 매출 — 숫자로 보는 엔진

### C1. 매출 원천 통합
| 원천 | 수집 | 비고 |
|---|---|---|
| 스마트스토어·오픈마켓 | 주문 엑셀 → 규칙 | 채널 주문번호로 중복 제거 |
| 자사몰 | 주문 엑셀/연동 → 규칙 | |
| 전화·방문·체험 | 입력 화면 | |
| B2B | 발주 입력 → 거래명세서·세금계산서 | |
| 수출 | 인보이스 입력 | |

### C2. 정산 대사 (매주 금)
주문 금액 − 수수료 − 배송비 = 정산 예정 → 실제 입금(`settlements`)과 비교 → 차이·미입금 목록.

### C3. 가격 정책
| 항목 | 규칙 |
|---|---|
| 채널별 가격표 | 소매·스마트스토어·자사몰·B2B·수출 (`products`) |
| 하한선 | 병당 원가 + 채널 수수료 + 배송비 + 주세 + 최소 마진 → 이보다 낮은 가격·할인은 경고 |
| 할인 | 캠페인 단위로만, 종료일 필수 |

### C4. 프로모션 효과
캠페인 기간 매출 − 평시 같은 기간 매출(전년·직전 4주 평균) = 순증 효과. 할인 비용·마케팅비와 비교해 ROI 계산.

### C5. 매출 예측 (규칙, AI 불필요)
- 시즌: 전년 같은 시즌 판매량 × (올해 1~3분기 성장률)
- 평시: 직전 8주 이동 평균
- 결과 → 병입 계획·부자재 발주 추천 (I-03, P-02 연결)

### C6. 엔진 계기판 (자동, 주간)
추력(매출) · 연비(마케팅비 대비 매출) · 점화(안내 반응률) · 재점화(재구매율) · 엔진 균형(사람 엔진 vs AI 엔진 매출) · 채널별 객단가 · 신규/재구매 비율
