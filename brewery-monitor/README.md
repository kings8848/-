# 킹스양조장 제어판 온도 자동 기록기

```
GiGAeyes(Sub ID, 제어판 카메라) ─ Seeker 화면 표시
   │ MacroDroid: 10분마다 3초 간격 캡처 3장
   ▼
Termux uploader.py ─ 제어판 부분만 잘라 JPEG로 전송
   ▼
Google Apps Script 웹앱 ─ Claude가 1~4호기 온도 판독
   ├─ 구글 시트 '기록'   : 시각·탱크·원주/상부/냉각℃·교반·상하차·신뢰도
   ├─ 구글 시트 '경보이력'
   └─ 텔레그램         : 기준 이탈·상하편차·판독실패·업로드중단 경보, 매일 07시 브리핑
```

| 파일 | 역할 | 설치 위치 |
|---|---|---|
| `apps_script/Code.gs` | 판독·기록·경보 | 구글 시트 → 확장 프로그램 → Apps Script |
| `seeker/uploader.py` | 캡처 묶어서 전송 | Seeker의 Termux |
| `seeker/start.sh` | 업로더 상시 실행 | Seeker의 Termux |
| `tests/` | 로직 테스트 | (개발용) |

## 0단계. 준비 (10분)

- [ ] **Claude API 키**: console.anthropic.com → 결제 크레딧 충전(처음엔 $10) → API Keys → 키 생성
- [ ] **텔레그램 봇**: 텔레그램에서 `@BotFather` → `/newbot` → 이름 입력 → **봇 토큰** 받기 → 내 봇에게 "안녕" 한 번 보내기
- [ ] **비밀 문자열(UPLOAD_TOKEN)**: 아무도 못 맞힐 20자 이상 영문+숫자 (예: `kings-7Hq2xP9vLm4Rt8Wz`)

## 1단계. 구글 시트 + Apps Script (15분)

1. 구글 드라이브 → 새 스프레드시트 → 이름 `킹스_발효온도기록`
2. 메뉴 **확장 프로그램 → Apps Script** → 기본 코드 전부 지우고 `Code.gs` 내용 붙여넣기 → 저장
3. 왼쪽 ⚙ **프로젝트 설정 → 스크립트 속성 추가**

   | 속성 | 값 |
   |---|---|
   | `ANTHROPIC_API_KEY` | Claude API 키 |
   | `UPLOAD_TOKEN` | 비밀 문자열 |
   | `TELEGRAM_BOT_TOKEN` | 봇 토큰 |
   | `MODEL` | (선택) 아래 비용표 참고 |

4. 편집기 상단 함수 선택에서 **`setup`** → ▶ 실행 → 권한 허용 (시트·드라이브·외부요청)
   → 시트에 `기록`, `설정`, `경보이력` 탭이 생깁니다.
5. 함수 **`getTelegramChatId`** 실행 → 실행 로그의 `채팅 ID: 123456789` → 속성 `TELEGRAM_CHAT_ID`에 추가
6. 함수 **`testTelegram`** 실행 → 텔레그램에 ✅ 메시지 오면 성공
7. **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자** (업로더가 로그인 없이 보내야 함. 비밀 문자열로 보호됨)
   - 배포 → **웹 앱 URL 복사** (`https://script.google.com/macros/s/.../exec`)

> 코드를 고친 뒤에는 **배포 관리 → 편집 → 새 버전**으로 다시 배포해야 반영됩니다.

## 4단계. Seeker 설정 (30분)

### 4-1. 화면·전원
- [ ] 설정 → 디스플레이 → 화면 자동 꺼짐: 최대 / 개발자 옵션 → **충전 중 화면 켜짐 유지** ON
- [ ] 설정 → 배터리 → **GiGAeyes, MacroDroid, Termux 배터리 최적화 해제**
- [ ] 상시 충전 + 거치대 (발열 적은 곳, 사무실에 둬도 됨)

### 4-2. GiGAeyes
- [ ] 설치 → **Sub ID 번호로 로그인** → 제어판 카메라 → **가로 전체화면**
- [ ] **수동 스크린샷 1장** → 갤러리에서 확인
  - 화면이 정상 → 계속 진행
  - **검은 화면** → 앱이 캡처 차단. 플랜 B(Seeker 카메라로 제어판 직접 촬영)로 전환 → 알려주세요
- [ ] 10~30분 그대로 두고 **영상이 저절로 멈추는지** 확인 (멈추면 4-3의 '재생 유지' 추가)

### 4-3. MacroDroid (Play 스토어, 무료 매크로 5개)
새 매크로 `제어판캡처`
- **트리거**: 정기 간격(Regular Interval) → **10분**
- **동작**
  1. 화면 켜기(Screen On)
  2. 스크린샷(Take Screenshot) → 저장 폴더 **`/sdcard/KingsPanel`**
  3. 대기 3초 → 스크린샷
  4. 대기 3초 → 스크린샷
- (영상이 멈추는 경우) 1번 앞에 **앱 실행: GiGAeyes** + **UI 상호작용(클릭)**으로 카메라 화면/전체화면 버튼 누르기 추가
- 스크린샷 동작은 접근성 권한을 요구합니다 → 허용

> 저장 폴더를 고를 수 없는 버전이면 기본 스크린샷 폴더(예: `/sdcard/Pictures/Screenshots`)를 `uploader.py`의 `WATCH_DIR`에 적으세요. 단, 그 폴더의 다른 스크린샷도 전송되니 전용 폴더를 권장합니다.

### 4-4. Termux (F-Droid에서 설치. Play 스토어 버전은 구버전이라 쓰지 마세요)
Termux 열고 한 줄씩 입력:
```bash
pkg update -y && pkg install -y python python-pillow termux-api
termux-setup-storage            # 저장소 권한 허용
mkdir -p ~/kings && cd ~/kings
# uploader.py, start.sh 를 이 폴더에 복사 (아래 방법 중 하나)
#  - GitHub에서 받기: pkg install git && git clone <저장소 주소>
#  - 또는 nano uploader.py 로 열어 붙여넣기
nano uploader.py                # 맨 위 ENDPOINT, UPLOAD_TOKEN 입력 → Ctrl+O 저장, Ctrl+X 종료
python uploader.py --once       # 시험 전송
```
`전송 OK: 3장 → 기록 4줄` 이 나오고 시트에 4줄이 생기면 성공. 그다음:
```bash
chmod +x start.sh
nohup ./start.sh > /dev/null 2>&1 &
```
- 재부팅 후 자동 시작: **Termux:Boot**(F-Droid) 설치 → `mkdir -p ~/.termux/boot && cp ~/kings/start.sh ~/.termux/boot/`
- 로그 보기: `tail -f ~/kings/uploader.log`

### 4-5. 판독 정확도 올리기 (첫날 꼭)
1. 드라이브 `킹스_제어판캡처` 폴더의 이미지를 열어 제어판이 화면에서 차지하는 범위 확인
2. `uploader.py`의 `CROP = (왼쪽, 위, 오른쪽, 아래)` 비율로 제어판만 남기기 (예: `(0.20, 0.05, 0.80, 0.95)`)
3. 시트 `기록`의 `신뢰도`가 대부분 `high`인지 확인
   - `low`가 많으면: KT 기사에게 **카메라를 제어판 정면·근접으로 조정** 요청, 야간 적외선 반사 확인

## 비용 (10분 간격 = 하루 144회, 1회 캡처 3장 기준 추정치)

| `MODEL` 값 | 성격 | 1회 | 월 예상 |
|---|---|---|---|
| `claude-opus-5-5` (기본값) | 판독 정확도 최상 | 약 $0.035 | **약 $150 (약 21만 원)** |
| `claude-sonnet-5-5` | 중간 | 약 $0.017 | 약 $75 (약 10만 원) |
| `claude-haiku-5-5` | 최저가 | 약 $0.001 | **약 $4 (약 6천 원)** |

- 실제 비용은 console.anthropic.com → Usage에서 확인하세요. 이미지 크기·자르기에 따라 달라집니다.
- 비용 조절 방법: ① 모델 변경(스크립트 속성 `MODEL`) ② 간격 15~30분 ③ 캡처 2장(`MAX_PER_GROUP = 2`)
- 권장: 첫 1~2일은 기본값으로 정답 기준을 잡고, 같은 캡처로 저가 모델 결과를 비교해 보고 결정.
- Opus/Sonnet은 안전 분류기가 드물게 판독을 거절하면 대체 모델로 자동 재시도(`fallbacks: "default"`)하도록 켜 두었습니다.

## 경보 종류

| 경보 | 조건 | 기본값 |
|---|---|---|
| 고온/저온 | 원주온도가 설정 범위 이탈 | `설정` 시트 |
| 상하편차 | \|상부 − 원주\| > 상하차_최대 | 5℃ |
| 판독실패 | 원주온도 연속 판독 불가 | 3회(30분) |
| 화면이상 | 제어판이 안 보임(영상 오류 등) | 3회 |
| 업로드중단 | 기록이 끊김(Seeker 꺼짐·와이파이) | 40분 |

같은 경보는 `경보간격_분`(60분) 안에 한 번만 보냅니다. 모든 경보는 `경보이력` 시트에 남습니다.

## 문제 해결

| 증상 | 확인 |
|---|---|
| `unauthorized` | uploader.py와 스크립트 속성의 `UPLOAD_TOKEN`이 같은지 |
| `Claude HTTP 401` | API 키 오타 / 크레딧 잔액 |
| 시트에 기록은 되는데 값이 빈칸 | 캡처 이미지 확인 → CROP 조정, 카메라 각도 |
| 업로드중단 경보 | Seeker 화면·와이파이·`tail ~/kings/uploader.log` |
| 코드 수정이 반영 안 됨 | Apps Script **배포 관리 → 새 버전** |
