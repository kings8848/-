# 킹스 AI 운영 도면 v1 (2026-11-04)

## 1. 영상 구조 요약 (캡처 16장 분석)

| 단계 | 영상의 규칙 | 핵심 의도 |
|---|---|---|
| 01 지시 등록 | CEO 원문은 **절대 수정 안 함** | 나중에 해석이 맞았는지 대조하는 기준 |
| 02 1차 토론 | 전원 의견, **관련 높으면 깊게·낮으면 짧게**(심도 차등 / 전원 깊게 / 생략) | 무관해 보이는 시각이 사고를 막음(저작권 누락을 1명만 잡은 사례) |
| 03 방향 정리 | 비서실장이 토론을 정리해 방향 승인 | 혼자 판단 방지 |
| 04 분해·배정 | **태스크 1개 = 담당 1명 = 산출물 1개**, 선행관계·**검수 기준을 이때 확정**(나중 추가 불가), 프롬프트에 '회사의 기억' 전부 탑재 | 같은 조사 반복 방지 |
| 05 수행 | 선행 끝나야 시작, 산출물은 태스크 폴더, **첫 줄에 '이 문서에서 알 수 있는 것'** | 다음 사람이 첫 줄만 보고 열지 말지 결정 → 토큰 절약 |
| 06 일괄 검수 | 전원 제출 후 **한 번에** 검수: 통과 / 반려→재작업 / 불가→재분해. **반려 3회면 CEO로**, 앞 회차 지적을 다음 프롬프트에 포함 | 검수 비용 억제, 같은 지적 반복 방지 |
| 07 전략 검토 | **다른 모델(GPT)이 독립 검토**, **승인권 없음·권고만**. 확정안이 없으면 검토 시작 안 함 | 같은 모델의 사각지대 보완, 자동 재작업 루프(토큰 폭증) 차단 |
| 08 최종 판단·게시 | 비서실장이 권고 반영 여부 결정 → 게시·최종 보고 | 승인 책임 한 곳 |
| 화면 | CEO 홈·메신저(지시별 채널)·검수함·작업 큐(성공/소요초/로그)·전략 검토·발행 큐·회사의 기억 | 진행 상황을 CEO가 한 화면에서 확인 |

## 2. 킹스에 맞게 고친 판단

| 구분 | 결정 | 이유 |
|---|---|---|
| **가져온다** | ① 원문 불변 ② 1담당·1산출물·검수기준 선확정 ③ 첫 줄 요약 ④ 일괄 검수·반려 3회 상신 ⑤ 회사의 기억 ⑥ 작업 큐(소요시간·로그) ⑦ 승인권 분리(외부 발송·게시·제출은 대표 승인) | 전부 '실증·재현'을 강화 → 어제 45점 감점 사유(반복 기록·증거 부족)와 직결 |
| **줄인다** | 10명 조직 → **역할 8개를 손사장 1명이 순차 수행**, 토론은 기본 '생략', 위험 업무만 '심도 차등' | 1인 양조장은 데이터 연결이 병목. 에이전트 수를 늘리면 토큰·관리비만 증가 |
| **조건부** | 다른 모델 독립 검토는 **세무·지원사업 제출·대외 게시·가격 결정**에만 | 매 건 하면 비용 폭증. 영상도 '필요한 의견만' 강조 |
| **버린다** | SNS 자동 게시(Threads) 선행 구축 | 킹스 우선순위는 정산·재고·출고 → 판매 연결이 먼저 |

## 4. 구현 위치

| 보완 | 파일 | 확인 방법 |
|---|---|---|
| 원문 불변(해시 봉인) | `ops/company/workflow.py new` | `verify` 실행 시 원문 변경되면 실패 |
| 1담당·1산출물·검수기준 선확정 | `workflow.py task` | 배정 후 기준 추가 시도 → 거부 |
| 첫 줄 요약 | 운영검증 보고서 첫 줄, 이 문서 첫 줄 | `workflow.py review`가 첫 줄 없으면 자동 반려 |
| 일괄 검수·반려 3회 상신 | `workflow.py review` | 3번째 반려 시 상태 `CEO상신` |
| 지적 이력 전달 | 태스크 `history` | 다음 회차 `brief` 출력에 포함 |
| 독립 검토 권고만 | `workflow.py advise` | 상태를 바꾸지 못함(테스트) |
| 회사의 기억 | `ops/company/memory.md` | `brief` 출력 맨 앞에 탑재 |
| 작업 큐 소요시간 | `state/runs.jsonl`의 `duration_sec` | 보고서 머리 |
| 승인권 분리 | 태스크 `external=true` → 대표 승인 전 `완료` 불가 | 테스트 |
